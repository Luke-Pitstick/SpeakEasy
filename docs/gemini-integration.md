# Gemini expansion integration

Model picker (October 24, 2026): Settings → Gemini → Choose phrase model loads OpenRouter's current text-model catalog, with search and six gaze-accessible choices per page. Choosing a model saves its ID locally and cancels pending phrase suggestions; subsequent expansion, refinement, and completion requests use that selection, including after restart. Model-list and save failures preserve the existing selection and expose retry/error state. The picker controls phrase suggestions only; conversation summaries and preference processing continue using their existing model. Requests retain latency-based routing without the previous Gemini-specific price ceiling, so the selected model's pricing applies. The public catalog is loaded without sending credentials or conversation text.

Selected model: `google/gemini-3-flash-preview` through OpenRouter. Request up to six distinct complete suggestions, use approved conversational context, stream completed candidates, and disable reasoning. Dasher navigation remains on local PPM.

Initials expansion prompt revision (October 24, 2026): require grammatical, meaningful conversational utterances while preserving every initial, prefix, and locked word. Encourage natural contractions (exactly one initial and one word position per written contraction, never extra initials for its expanded words; `idk` matches “I don’t know” whereas `idnk` matches “I do not know”) and expressive wording supported by the input and conversation. Check agreement, verb forms, word order, and required function words before returning each line; prefer fewer good alternatives over padding the list with awkward or nonsensical phrases. These are model instructions, not a deterministic grammar guarantee; local validation enforces word constraints, and live phrase quality still needs evaluation.

Live follow-up: a 16-case comparison confirmed contractions and expressive phrases but also exposed grammatical and contextual failures in Gemini. Qwen3.8 Flash produced mostly natural accepted phrases but no constraint-valid choices in six cases. The app default remains unchanged. See [the complete live comparison](phrase-quality-live.md) for outputs, limitations, and the opt-in test command.

The development comparison on 60 public dialogue replies recovered the exact reference among six suggestions on 24/60 requests with context versus 6/60 without. Contextual first-valid latency was 0.97 s median / 1.38 s p95. These measurements inform the selection but do not establish production reliability or gaze usability. The benchmark harness, raw data and downloaded runtimes were removed at the user's request.

Implementation must keep the key and network requests in Electron's main process, validate requests and candidates, cancel superseded generations, reject stale revisions, and publish only at safe interaction boundaries. Model output cannot accept wording or trigger speech. Conversation is explicitly entered or added by the user, remains session-only, and must be clearable. Never send eye-tracking data.

Status: integrated into the desktop app. Open Menu → Conversation & Gemini, enable Gemini, and add partner turns or accepted messages. The most recent eight turns (up to 1,000 characters each) are retained for this session. New message preserves them; Clear conversation forgets them and cancels pending results. Persistent memory is not implemented.

The main process reads `OPENROUTER_TOKEN` from the environment or the app root `.env`; packaging excludes `.env`. Cloud generation defaults off each app launch. The renderer receives only configuration status, never credentials. Requests time out after 12 seconds and stop after six valid distinct candidates. Fewer than six can be returned if the provider produces invalid or duplicate lines; the app never invents replacements to fill slots.

The shared `ConversationTurn` contract distinguishes `me` from `partner`. The Cartesia voice integration appends finalized partner transcripts via `conversation-add`; partial transcripts must stay outside prediction context. Context edits invalidate request revisions. A finalized partner turn refreshes an existing expansion when cloud generation is enabled and input is paused. External transcript events must be queued during steering/dwell and dispatched at a safe boundary. `contextEpoch` increments on Clear conversation; voice must observe it to discard pending transcripts and reset its stream so forgotten context cannot return. Speech remains a separate explicit Speak/Preview action; see [voice integration](voice-integration.md).

Validation: the Electron app was checked with the configured OpenRouter key on October 24, 2026. With partner context “Would you like tea or coffee?” and initials `iwac`, six valid suggestions appeared, led by “I want a coffee.” The draft stayed unchanged until explicit Use. This was a live provider and native mouse check, not a real-user gaze evaluation. Automated checks cover fragmented streams, constraints, cancellation, timeout, stale revisions, context clearing/refresh, and existing synthetic gaze flows.
